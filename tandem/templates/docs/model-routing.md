# 모델 배치표

누구에게 무엇을 시킬지 정하는 문서다. **비용과 품질의 균형이 이 파일 하나에 걸려 있다.**

## 기본 원칙

> **한 단계 낮게 시작하고, 실제로 실패했을 때만 올린다.**

처음부터 최상위 모델을 쓰면 비용이 몇 배가 되는데 결과는 대부분 같다.
승급은 "어려워 보여서"가 아니라 "낮은 단계가 실패했으니까" 한다.

## Codex 모델

적응 단계에서 실제 계정의 모델로 채워진 값이다. 계정과 플랜에 따라 다르고,
최상위 모델은 기본 비활성일 수 있다. 바뀌면 이 표를 갱신한다.

| 모델 ID | 층 | 쓸 곳 |
|---|---|---|
| `{{MODEL_TOP}}` | 최상위 | 여러 단계에 걸친 자율 작업, 낮은 단계가 실패한 난제 |
| `{{MODEL_MID}}` | 중상위 | 복잡한 작업, 설계, 에이전트 워크플로. **실무 리드 기본값** |
| `{{MODEL_LIGHT}}` | 경량 | 대량 조사, 요약, 추출, 스펙이 확정된 기계적 작업. **일꾼 기본값** |

## 최상위 승급 조건

최상위 모델은 토큰당 비용이 크게 높다. **입력 길이가 임계를 넘으면 요율이 더 오르는 모델도 있다.**
다음 중 하나에 해당할 때만 쓴다.

1. 중상위가 같은 과제에서 **실제로 실패**했다 (결론 못 냄, 반론을 방어 못 함, 요구 조건 미충족)
2. 여러 단계를 스스로 이어가야 하는 긴 자율 작업이다
3. 총괄이나 팀장이 명시적으로 지정했다

승급하면 **산출물 머리에 승급 사실과 이유를 적는다.** 브리핑에도 올린다.
컨텍스트가 길어지지 않게 과제를 쪼갠다.

## 추론 강도

모델만큼 중요한 레버다. 같은 모델도 강도에 따라 비용이 크게 달라진다.

| 강도 | 쓸 곳 |
|---|---|
| `low` | 추출, 목록화, 형식 변환 |
| `medium` | 일반 조사, 문서 초안. **기본값** |
| `high` | 설계, 판단이 필요한 작업, 적대적 검토 |
| `xhigh` | 낮은 강도가 실패한 난제 |
| 그 이상 | 쓰지 않는다. 명시적 지시가 있을 때만 |

모델별 지원 범위는 다르다. 적응 단계에서 확인한 값을 여기에 적는다.

## 승급 사다리

```
1단계  경량   + medium     ← 여기서 시작
2단계  중상위 + high       ← 1단계가 실패하면
3단계  최상위 + xhigh      ← 2단계가 실패하면. 기록 남김
```

옆으로 새는 길이 하나 있다.

```
Claude 교차 검수   ← Codex 계열이 공유하는 맹점이 의심될 때
```

## Claude 측을 쓰는 조건

Claude는 **판단과 보고**에만 쓴다. 실무로 내려가면 이 구조의 의미가 없다.

| 자리 | 호출 조건 |
|---|---|
| 총괄 | 게이트, 최종 판정, 보고 |
| 팀장 | 과제 분해, 검수, 종합. 과제마다 1-2회 |
| 전달책 | `codex exec` 호출. 산출물 본문을 절대 읽지 않는다 |
| 교차 검수 | 되돌리기 어려운 결정이거나 요청이 있을 때만 |

## 적대 검토의 모델 분리

일부 Codex 버전에서 **하위 일꾼마다 모델을 지정하는 기능이 막혀 있다.**
그런 버전에서는 하위 일꾼이 리드의 모델을 물려받아, 제안자와 반박자가 같은 모델이 된다.

그래서 적대 검토는 **하위 일꾼으로 만들지 않고 별도 세션으로 실행한다.**
실행할 때 `-m`으로 다른 모델을 박으면 버전과 무관하게 분리가 보장된다.

```
제안: codex exec -m {{MODEL_MID}} ...
반박: codex exec -m {{MODEL_TOP}} ...
```
